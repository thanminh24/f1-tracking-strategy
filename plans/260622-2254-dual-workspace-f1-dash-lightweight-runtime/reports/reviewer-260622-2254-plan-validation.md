# Plan red-team and validation

Date: 2026-06-22

## Verdict

Ready for user review. Dependency order and release gates are coherent. No implementation should begin before the distribution/license decision and capability contract.

## Challenges resolved

- Two workspaces risk duplicate systems. Plan now requires one subscription, store, selectors, adapters, and headless widget layer.
- No live race makes visual work deceptively easy. Plan separates deterministic fixture, archive, and true-live validation labels.
- Removing race cache alone does not make a light image. Dependency split and optional strategy runtime address Torch/archive weight.
- ONNX could silently change policy behavior. It is a measured experiment with preprocessing, recurrent state, action, and rollout parity gates.
- Radio coverage is neither universal nor stable. Contract allows absent/late/expired recordings and forbids invented transcript claims.
- F1 Dash cloning creates AGPL/trademark risk. Clean-room/license gate precedes visual implementation and public distribution.
- A dense professional screen can become unusable. Pit Wall uses operator-task presets while preserving shared driver/session context.

## Consistency checks

- Every phase has measurable success criteria.
- Default boot requires no historical download.
- Optional capability failure cannot take down live timing.
- Model selection follows benchmark definition, not the reverse.
- Final release distinguishes fixture, archive, and real-live evidence.

## Unresolved questions

- Public or private distribution?
- Accepted image-size/startup budgets?
- One default command plus an analysis override acceptable?
